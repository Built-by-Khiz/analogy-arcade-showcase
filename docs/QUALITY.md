# Quality and responsible design

## Analogy quality

A useful analogy explains the core idea without pretending the two worlds are identical. The “Where the analogy breaks” section is part of the teaching experience, not an afterthought.

The review stage considers clarity, factual accuracy, analogy fit, usefulness, engagement, and safety. The rewrite stage runs for each generated request in the retained workflow.

## Learning experience

A small quiz invites the learner to retrieve the idea instead of only reading it. Correct choices use a green state; a selected incorrect choice uses amber and reveals the correct answer. Text explains the outcome so color is not the only signal.

The refreshed UI supports keyboard focus, clear form labels, responsive layouts, and reduced-motion preferences. Generated text is rendered without executing raw HTML.

## Honest service states

The app distinguishes a static sample from generated output. It does not present fabricated AI output when the service is unavailable. Live request limits and failures are visible to the user.

## Validation scope

Local checks cover input and response handling, sample and quiz behavior, feedback validation, shared quota boundaries, and the refreshed desktop/mobile interface. Publication on Lovable is separate from this validation scope; these local checks do not establish live AI generation or storage behavior. No production usage or quality metric is claimed here.
